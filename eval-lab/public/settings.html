MCP server setup — UNICOMM line connector

The live-line service on this platform is fed by a read-only Model Context Protocol server that sits next to the MES database and exposes a small set of curated tools — never raw SQL. This is the same connector developed for the Comer Rokid build (connectors/mssql-unicomm-database). Installing it on an on-site host is a 15-minute job for IT personnel with database and network access.

◈
Design guarantees. The connector opens the SQL connection with read-only intent, ships no write path, and exposes only curated tools (workstation snapshot, phase results, technician on task, measurement history, session state). Plant directors query it in natural language from this platform — no SQL knowledge required on the floor.
1

Prerequisites

An on-site host (VM or container) with Node.js 20+, a read-only SQL login on the line database, and network reach to the MES SQL host — at Rockford that is WARKFSQL002 / database SSL04_FARGO. If the host is off the plant network, set up VPN access first (next section).

shell · smoke-test connectivity 
# confirm the SQL host answers before installing anything
sqlcmd -S WARKFSQL002,1433 -d SSL04_FARGO -U <READONLY_SQL_USER> -Q "SELECT 1"
2

Install the connector

The connector lives on the connectors/mssql-unicomm-database branch of the Comer Rokid repository. Access to the repository is granted by Omnia per developer.

shell · install 
git clone https://github.com/AldoOmnia/comer-rokid-demo.git
cd comer-rokid-demo
git checkout connectors/mssql-unicomm-database
cd connectors/mssql-unicomm-database
npm install && npm run build
3

Configure the environment

All open values are flagged — host and database names are per-site and owned by Comer IT. Never commit this file.

.env 
MSSQL_HOST=WARKFSQL002            # ← MES SQL host — per site
MSSQL_PORT=1433
MSSQL_DATABASE=SSL04_FARGO        # ← line database — Rockford axle line
MSSQL_USER=<READONLY_SQL_USER>      # ← read-only login provisioned by Comer IT
MSSQL_PASSWORD=<READONLY_SQL_PASSWORD>
MSSQL_ENCRYPT=true
STATION_NUMBER=100                # ← default station in scope (ST100 · Pinion Guide)

What the connector code looks like

A representative excerpt: a read-only connection pool and one curated tool. The full connector ships five tools shaped exactly like this — no free-form SQL surface.

src/connector.ts · sample 
import sql from "mssql";

// Read-only intent at the driver level — the connector has no write path.
const pool = new sql.ConnectionPool({
  server: process.env.MSSQL_HOST!,        // WARKFSQL002
  database: process.env.MSSQL_DATABASE!,  // SSL04_FARGO
  user: process.env.MSSQL_USER,
  password: process.env.MSSQL_PASSWORD,
  options: { encrypt: true, readOnlyIntent: true },
  pool: { max: 4 },
});

/** Curated tool: the live snapshot for one workstation. */
export async function fetchWorkstationSnapshot(stationNumber = 100) {
  const db = await pool.connect();
  const r = await db.request()
    .input("station", sql.Int, stationNumber)
    .query(/* parameterized TOP-1 snapshot query — station, step,
             technician, serial, latest measurements + verdicts */ QUERY);
  return r.recordset[0] ?? null;
}

Point this platform at the bridge

Once the connector's HTTPS façade (/v1/unicomm/health, /v1/unicomm/workstation) is reachable, set two environment variables on the platform deployment. The Live line card on the home page switches from demo data to live automatically — no UI work.

platform environment · Render 
LINE_BRIDGE_URL=https://<ON_SITE_BRIDGE_HOST>:8443   # ← the on-site connector façade
LINE_BRIDGE_API_KEY=<ROTATED_API_KEY>              # ← issued per deployment, rotate quarterly
The connector never leaves the plant network — this platform reaches it only through the authenticated HTTPS façade above. SQL credentials stay on the on-site host.

VPN access — Cisco

The MES SQL host is only reachable from the plant network. Comer's remote access runs on the Cisco stack (Secure Client / AnyConnect). Off-site connector hosts and developer workstations connect through it before anything in the MCP section will resolve.

▲
Open variables — confirm with Comer IT before rollout. These values are site- and provider-specific; the network provider can change and the gateway, group profile and DNS values move with it. Nothing below is hard-coded in the connector.
  • <VPN_GATEWAY> — the Cisco headend, e.g. vpn.comer-plant.example
  • <GROUP_PROFILE> — the tunnel group assigned to MES/engineering access
  • <AD_USERNAME> — the Active Directory account (MFA push follows)
  • <BRIDGE_HOST_IP> — the on-site host running the MCP connector
1

Interactive access — Cisco Secure Client

Developer workstations use the Secure Client UI or its CLI. Install from the Comer IT software portal, then:

shell · macOS / linux CLI 
# Cisco Secure Client CLI (macOS path shown; Windows: "Cisco Secure Client" app)
/opt/cisco/secureclient/bin/vpn connect <VPN_GATEWAY>
# → group: <GROUP_PROFILE> · user: <AD_USERNAME> · approve the MFA push
2

Headless access — connector host

For the unattended host that runs the MCP connector, openconnect speaks the AnyConnect protocol and runs cleanly under systemd:

shell · headless host 
sudo openconnect --protocol=anyconnect \
  --user=<AD_USERNAME> \
  --authgroup=<GROUP_PROFILE> \
  <VPN_GATEWAY>

Prefer a service account with a certificate profile over a personal AD login for anything unattended — request it from Comer IT.

3

Firewall / split-tunnel request

The connector needs exactly two flows. Submitting this as the firewall request keeps the access review simple:

access request · two rules 
# 1 — connector host to the MES SQL server (read-only login)
allow tcp <BRIDGE_HOST_IP> -> WARKFSQL002:1433

# 2 — platform egress to the connector's HTTPS façade
allow tcp <PLATFORM_EGRESS_IP> -> <BRIDGE_HOST_IP>:8443
4

Verify end-to-end

shell · through the tunnel 
# SQL reachability (expect one row: 1)
sqlcmd -S WARKFSQL002,1433 -d SSL04_FARGO -U <READONLY_SQL_USER> -Q "SELECT 1"

# connector façade health (expect JSON with "config")
curl -H "x-api-key: <ROTATED_API_KEY>" https://<BRIDGE_HOST_IP>:8443/v1/unicomm/health
Provider note: Comer runs Cisco today. If the network provider changes, only the gateway, group profile and client software in this section change — the MCP connector, the firewall rule shapes and the platform wiring above stay identical.
